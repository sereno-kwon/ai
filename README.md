# Rubi Workshop AI 자전거 상담

고객이 용도, 주행 환경, 키와 예산을 이야기하면 AI가 루비워크샵 취급 모델 중 어울리는 모델과 사이즈 방향을 안내하고, 슈즈 사이즈와 부품 스펙·규격 질문에도 답하며, "채널톡으로 상담 이어가기"를 누르면 상담 요약이 채널톡으로 넘어가는 고객용 상담 앱입니다.

```
ai.rubiworkshop.com (정적 사이트, 저장소 루트)
        │  POST (text/plain JSON)
        ▼
Google Apps Script 웹앱 (apps-script/Code.gs)
        ├─ 구글 시트: 모델 · 지오메트리 · 출고사례 · 슈즈 · 부품 · 안내 → AI 지식
        ├─ 상품 탭: rubiworkshop.com 상품 페이지 아코디언 자동 동기화 (매일)
        ├─ 브랜드사이트 탭: bastioncycles.co.kr 같은 브랜드 코리아 사이트 자동 동기화 (매일)
        ├─ Claude API → 답변 + 추천 카드
        ├─ 상담로그 탭에 기록 (전화번호·이메일 자동 가림)
        └─ (선택) 채널톡 팀챗 그룹에 요약 알림
고객 화면 → ChannelIO('openChat') 로 요약이 입력된 채널톡 대화창 열림
```

## 폴더 구성

| 파일 | 내용 |
|---|---|
| `index.html` | 상담 화면 (루비 톤: 영문 Pretendard, 한글 에스코어 드림, 굵기 400) |
| `og.png` | 공유 이미지 1200×630 |
| `robots.txt`, `sitemap.xml`, `CNAME` | 검색 최적화와 도메인 |
| `apps-script/Code.gs` | 백엔드 전체 |
| `apps-script/appsscript.json` | 시간대(서울), 웹앱 권한 |

## 1. 지식 시트 만들기

1. 구글 드라이브에서 새 스프레드시트를 만듭니다. 이름 예: `00_AI 상담 자료`
2. 확장 프로그램 → Apps Script를 열고 `Code.gs` 내용을 붙여넣습니다.
3. 편집기 왼쪽 톱니바퀴(프로젝트 설정) → "appsscript.json 표시"를 켜고 `appsscript.json` 내용을 붙여넣습니다.
4. 함수 목록에서 `setup` 을 실행하고 권한을 허용합니다. 탭 12개(모델, 지오메트리, 출고사례, 슈즈, 부품, 상품, 브랜드사이트, 브랜드사이트 내용, 상단이미지, 사이즈가이드, 안내, 상담로그)가 생깁니다. 이미 세팅한 시트라면 `setup`을 한 번 더 실행하면 없는 탭만 추가됩니다.
5. 시트를 새로고침하면 상단에 **AI 상담** 메뉴가 생깁니다.

### 탭별 작성 요령

- **모델**: AI는 이 탭에 있는 모델만 추천합니다. `노출`에 N을 넣으면 숨겨집니다. `링크`에 루비워크샵 모델 페이지 주소를 넣으면 추천 카드에 "자세히 보기"가 붙습니다(https만).
- **지오메트리**: 사이즈 추천의 근거입니다. 지오메트리 앱 데이터가 있으면 그대로 옮겨도 됩니다. `추천 키`, `추천 인심` 칸이 가장 중요합니다.
- **출고사례**: 고객 이름, 연락처 없이 체형·용도·빌드만 적습니다. 예: `2026-09 | Crust | Evasion | 54 | 176 | 81 | 주말 투어링 | 프론트랙, 650B | 장거리 만족`
- **슈즈**: 브랜드 사이즈표를 발 길이(mm) 기준으로 옮깁니다. 한 사이즈에 한 행. `사이즈 팁`에 "발볼 넓으면 반 사이즈 업", "QUOC은 정사이즈" 같은 실제 판매 경험을 적어 두면 AI가 그대로 안내합니다. 이 탭에 없는 브랜드는 사이즈를 추천하지 않고 시착을 권합니다.
- **상품**: 직접 쓰지 않습니다. 아래 "루비워크샵 상품 자동 동기화"가 채웁니다. 추천에서 빼고 싶은 상품만 `노출`을 N으로 바꾸면 되고, 다음 동기화 때도 N이 유지됩니다.
- **부품**: 루비워크샵 사이트에 아직 없는 부품을 보충할 때만 씁니다(상품 탭과 중복되면 내용이 엇갈릴 수 있습니다). 제품마다 `규격·호환`에 호환 판단에 필요한 수치를 적습니다. 예: BB는 규격·쉘 폭·스핀들 지름, 허브는 OLD·액슬 방식·브레이크 마운트, 페달은 스핀들 나사, 시트포스트는 지름·셋백, 체인링은 BCD·티스. AI는 이 칸을 근거로 "자료상 맞는 규격"까지만 말하고 최종 호환은 상담원 확인으로 넘깁니다.
- **안내**: 쇼룸, 운영시간, 계약금·리드타임·워런티 원칙처럼 AI가 안내해도 되는 문장. 예시 행은 실제 내용으로 바꿔 주세요.
- **상담로그**: 자동 기록. 고객이 무엇을 묻는지, 어떤 모델이 추천되는지 주간 점검용입니다.

자료를 고친 뒤 바로 반영하려면 **AI 상담 → 자료 새로고침**을 누르세요(그냥 두면 10분 뒤 반영).

## 1-1. 루비워크샵 상품 자동 동기화

부품, 슈즈, 자전거 스펙은 rubiworkshop.com 상품 페이지의 아코디언에서 가져옵니다.

- 읽는 곳: `rubiworkshop.com/sitemap.xml`에 있는 상품 페이지(`/shop_view/번호`) 전부
- 가져오는 내용: 상품명, 판매가, **제품 요약**, 그리고 제품 특징과 장착·호환·사이즈·관리 안내처럼 브랜드 이야기와 배송·교환 안내를 뺀 나머지 아코디언
- 저장: 상품 탭 (상품번호, 상품명, 분류, 판매가, 제품 요약, 스펙·안내, 링크, 노출, 동기화, 검색키)
- 사이트에서 내려간 상품은 다음 동기화 때 상품 탭에서도 지워집니다.

**처음 실행**
1. 시트 메뉴 **AI 상담 → 루비워크샵 상품 동기화 (지금)**을 누릅니다. 외부 사이트 접속과 트리거 권한을 묻으면 허용합니다.
2. 상품이 780개 안팎이라 한 번에 다 못 읽으면 1분 뒤 자동으로 이어서 읽습니다. 보통 10분 안쪽에 끝납니다.
3. **AI 상담 → 매일 자동 동기화 켜기**를 한 번 눌러 두면 매일 새벽 4시에 갱신됩니다.

**AI가 쓰는 방식**
- 상품 목록(상품명, 판매가)은 늘 참고하고, 상세 스펙은 대화와 관련된 상품 최대 6개만 골라 그때그때 넘깁니다. 780개 전체 스펙을 매번 넣으면 비용과 응답 시간이 크게 늘기 때문입니다.
- 색상만 다른 같은 제품은 하나로 묶고 "다른 색상·옵션"으로 함께 알려 줍니다.
- 아코디언에 적힌 "확인이 필요합니다" 같은 주의 문구는 빼지 않고 전달합니다.
- 상품 페이지 아코디언을 고치면 다음 동기화부터 AI 답변에 반영됩니다. 바로 반영하려면 동기화를 한 번 더 누르세요.

## 1-2. 브랜드 사이트 동기화 (바스티온 등)

맞춤 제작 브랜드처럼 루비워크샵 상품 페이지에 없는 정보는 브랜드 코리아 사이트에서 가져옵니다.

- **브랜드사이트 탭:** 읽을 사이트 목록입니다. `setup`이 `바스티온 사이클 | https://bastioncycles.co.kr/ | Y`를 넣어 둡니다. 크러스트, 팔리, 츠바사 사이트도 한 줄씩 추가하면 같은 방식으로 읽습니다.
- **브랜드사이트 내용 탭:** 자동으로 채워집니다. 페이지의 `<section id="...">` 단위로 글을 저장하고 갤러리는 뺍니다. 표와 스펙 목록(dl)은 "제작기간: 180일"처럼 항목별로 정리됩니다.
- **AI 사용 방식:** 이 내용은 항상 AI 자료에 들어갑니다. 브랜드 모델, 공법, 제작 과정, 시작 가격은 사이트에 적힌 대로만 안내합니다. "부터"로 표기된 가격은 옵션에 따라 달라진다고 덧붙입니다.
- **운영시간과 연락처:** 안내 탭이 기준입니다. 브랜드 사이트에 적힌 시간이 달라도 안내 탭을 따릅니다.
- **갱신:** 상품 동기화를 시작할 때 함께 갱신되고, 메뉴의 **브랜드 사이트 동기화 (지금)**으로 바로 갱신할 수도 있습니다. 사이트를 읽지 못하면 예전 내용을 그대로 둡니다.

## 1-3. 상단 이미지 (룩북에서 매일 갱신)

상담 화면 맨 위 사진은 고정 이미지가 아니라 루비워크샵 룩북에서 매일 새로 가져온 사진들이 천천히 바뀌며 나옵니다.

- **상단이미지 탭:** 매일 rubiworkshop.com/lookbook 첫 페이지 게시물 사진, 제목, 게시물 링크가 채워집니다(출처: 룩북 자동). 룩북에 새 글을 올리면 다음 날 상단 사진에도 들어갑니다.
- **직접 추가:** 원하는 사진은 행을 추가하고 출처 칸에 `직접`이라고 적으면 됩니다. 이 행은 동기화해도 지워지지 않습니다.
- **빼기:** 보이지 않게 하려면 노출을 N으로 바꿉니다. 룩북 자동 행도 다음 동기화 때 N이 유지됩니다.
- **화면 동작:** 방문할 때마다 시작 사진이 달라지고, 6초마다 천천히 넘어갑니다(`index.html`의 `HERO_SECONDS`로 조절). 가로 사진만 쓰고, 사진 왼쪽 아래 제목을 누르면 해당 룩북 게시물로 이동합니다. 마우스를 올리면 멈추고, 동작 줄이기 설정을 켠 방문자에게는 바뀌지 않습니다.
- **갱신:** 매일 동기화 때 함께 갱신되고, 메뉴 **상단 이미지 동기화 (지금)**으로 바로 갱신할 수 있습니다. API를 연결하기 전(미리보기 모드)에는 페이지에 넣어 둔 기본 룩북 사진 10장이 돌아갑니다.

## 1-4. QUOC 사이즈 가이드

QUOC 슈즈 사이즈는 [rubiworkshop.com/quoc-size-guide](https://rubiworkshop.com/quoc-size-guide)와 똑같이 답합니다.

- **조견표:** 매일 가이드 페이지의 조견표(EU, 발 길이 범위, 신발 길이, UK, US)를 읽어 사이즈가이드 탭에 저장합니다. 페이지를 고치면 다음 동기화부터 반영되고, 읽지 못하면 이전 표(처음에는 코드에 넣어 둔 2026-11-11 기준 표)를 씁니다.
- **계산:** 고객이 실측 발 길이를 말하면(예: "발 길이 재 보니 268mm", "발길이 27.5cm") Apps Script가 가이드와 같은 규칙으로 먼저 계산해 AI에 넘깁니다. AI는 숫자를 다시 계산하지 않고 그대로 안내합니다.
  - 다음 사이즈 시작점까지 2mm 이내면 "끝에 가깝습니다. 다음 사이즈도 함께 신어 보세요"
  - 범위의 앞 1/3 이내면 "앞쪽, 발끝 여유 넉넉"
  - 그 사이는 "가운데, 정사이즈"
  - 범위 사이 값(예: 255.5mm)은 다음 사이즈, 조견표 밖의 값은 가이드와 같은 안내 문구
  - 가이드 페이지에서 직접 확인한 발 길이 43개 값으로 대조해 결과가 모두 같았습니다.
- **운동화 사이즈:** "운동화 270 신어요"처럼 평소 신발 사이즈만 말하면 사이즈를 정하지 않고, 발 길이 재는 법을 안내해 실측값을 다시 묻습니다.
- **함께 안내하는 것:** 발볼이 넓거나 발등이 높으면 레이스 모델(그랜투어러 XC 레이스, 이스케이프, M 프로 레이스), 사이즈 가이드 링크, 쇼룸 시착.
- **QUOC 외 슈즈:** 슈즈 탭 기준으로만 안내하고, 자료가 없으면 환산하지 않고 시착을 권합니다.

## 2. Claude API 키 넣기

1. console.anthropic.com 에서 API 키를 발급합니다. 결제 한도(월 사용 한도)도 함께 걸어 두는 것을 권합니다.
2. Apps Script → 프로젝트 설정 → 스크립트 속성에 추가:

| 속성 | 값 |
|---|---|
| `ANTHROPIC_API_KEY` | 발급받은 키 (필수) |
| `CLAUDE_MODEL` | 비워 두면 `claude-sonnet-5-5` |
| `DAILY_LIMIT` | 하루 최대 AI 호출 수, 기본 400 |

3. **AI 상담 → 연결 테스트**로 답변이 나오는지 확인합니다.

키는 Apps Script 안에만 있고 고객 화면에는 노출되지 않습니다.

## 3. 웹앱으로 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**
2. 실행 사용자: **나**, 액세스 권한: **모든 사용자**
3. 나온 주소(`https://script.google.com/macros/s/…/exec`)를 복사합니다.
4. 코드를 고친 뒤에는 **배포 관리 → 수정 → 새 버전**으로 올려야 반영됩니다(주소는 그대로 유지).

## 4. 상담 화면 연결

`index.html` 아래쪽 `CONFIG`를 채웁니다.

```js
var CONFIG = {
  API_URL: "https://script.google.com/macros/s/…/exec",
  CHANNEL_PLUGIN_KEY: "채널톡 플러그인 키",
  HANDOFF_AFTER: 2,
  MAX_TURNS: 16
};
```

- `API_URL`이 비어 있으면 **미리보기 모드**(예시 답변)로 동작합니다.
- `CHANNEL_PLUGIN_KEY`: 채널톡 데스크 → 설정 → 채널 설정 → 일반 설정의 플러그인 키. 아임웹 페이지처럼 채널톡이 이미 깔린 곳에 코드를 넣을 때는 비워 둡니다.
- 채널톡을 띄울 수 없으면 요약 창이 열리고 복사 버튼으로 전달할 수 있습니다.

## 5. 도메인 (다른 브랜드 사이트와 같은 방식)

1. 이 저장소(`sereno-kwon/ai`) 루트가 그대로 사이트입니다.
2. GitHub Pages(main 루트) 또는 Cloudflare Pages로 배포합니다.
3. DNS에 `ai` CNAME 레코드를 추가합니다. 다른 주소를 쓰려면 `CNAME`, `index.html`의 canonical·og:url·JSON-LD, `robots.txt`, `sitemap.xml`의 주소를 함께 바꿉니다.
4. 루비워크샵 상담(CONSULTING) 버튼이나 rubiworkshop.com/consulting 페이지에서 이 주소로 연결합니다.

## 6. (선택) 채널톡 팀챗 알림

고객이 "채널톡으로 상담 이어가기"를 누를 때, 같은 요약을 팀챗 그룹에도 올리고 싶으면 스크립트 속성에 추가합니다. 채널톡 Open API는 유료 플랜에서 쓸 수 있습니다.

| 속성 | 값 |
|---|---|
| `CHANNEL_ACCESS_KEY` / `CHANNEL_ACCESS_SECRET` | 채널톡 설정 → 보안 및 개발 → API 인증 키 |
| `CHANNEL_GROUP` | 알림 받을 팀챗 그룹 이름(예: AI 상담 알림) 또는 숫자 ID |
| `CHANNEL_BOT_NAME` | 보낼 봇 이름, 기본 "AI 상담" |
| `CHANNEL_API_BASE` | 기본 `https://api.channel.io/open/v5`. 채널톡이 엔드포인트 주소 이전을 공지하고 있으니, 알림이 멈추면 새 주소로 바꿔 넣습니다 |

## 안전장치

- 하루 호출 한도(`DAILY_LIMIT`), 한 상담 최대 16턴, 메시지 800자 제한
- AI는 시트에 없는 모델·수치를 지어내지 않고, 재고·할인·정확한 견적은 상담원 확인으로 넘기도록 지시되어 있습니다
- 고객에게 개인정보를 묻지 않으며, 실수로 적은 전화번호·이메일은 로그에서 가려집니다
- 자료 블록에 프롬프트 캐시를 걸어 같은 자료로 이어지는 상담의 비용과 응답 시간을 줄입니다
